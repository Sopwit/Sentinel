# CW-04.5 verified terminal input fix

The isolated investigation physically identified the blocking combination: a delayed `CSI 0n` reply to the unnecessary trailing `CSI 5n` query reaches Crossterm after the capability reader has returned. Crossterm's inner blocking terminal read defeats the requested input poll timeout. A keyboard event releases it. The user-observed failing poll lasted 16.155 seconds instead of 50 milliseconds; the isolated candidate completed polling in 51 milliseconds and presented at 79 milliseconds. See [isolated evidence](../core-warden-rust-terminal/REPORT.md).

## Production change

The proposed patch applied cleanly to the current working tree. The sole production source modification is five added lines in `cli/crates/sentinel-mascot/src/capability.rs`: guard and strip the upstream query's final `ESC[5n` before writing it. An unexpected upstream query shape safely falls back to text. There was no explicit `Response::Status` handler in this detector to remove; ignored upstream parser variants remain ignored. No status request is now generated by this path.

Actual Kitty/Sixel responses, cell validation, protocol selection, the existing 300 ms / 4096-byte limits and environment safety gates are unchanged. No timer, polling loop, forced redraw, screen clear or dependency was added. Production layout/player files and unrelated V3.3 changes were not edited. AgentRuntime, daemon, Desktop and Blender assets were not edited. No commit, push or merge.
