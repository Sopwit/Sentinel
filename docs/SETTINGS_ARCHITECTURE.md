# Settings, onboarding, and localization

`AppSettings` persists application preferences in the existing settings store. `ModelService` owns the selected provider and model; `ExtensionService` presents MCP, plugin, and skill state from their native services; `WorkspaceService` resolves global, preset, workspace, and session preferences; `VoiceSessionService` owns live audio devices and speech runtime metadata. `SettingsService` composes product snapshots and validates its supported writes. It does not store a second copy of subsystem state.

The product section IDs are `general`, `appearance`, `models`, `agent`, `tools`, `extensions`, `workspaces`, `speech`, `privacy`, `network`, `storage`, `notifications`, and `advanced`. Only sections with implemented snapshot rows are returned to clients. Rows include stable IDs, values, defaults, sources, allowed values, search terms, scope, availability, and sensitivity. Workspace overrides retain their separate profile document; restoring inheritance removes only the requested override. Global reset operates on an individual setting or safe section and does not erase user data.

The existing desktop Settings page groups controls into Interface, AI, Voice, Memory, Security, and System. Some QML controls still use older view-model properties. Provider/model selection now goes through `ModelService`; local endpoint setters validate through `SettingsService` before runtime reconfiguration. API key getters at the desktop boundary return no secret. Provider snapshots report credential presence, never the value. Provider, web-search, proxy, and remote MCP header credentials use the native `CredentialStore` through their owning services. On first read, a legacy settings value is copied to the secure backend, read back for confirmation, and then removed from settings. A failed secure write leaves the legacy value intact for recovery. Remote MCP configuration retains stable secret references. Plugin credential declarations and presence use the extension service boundary.

`NetworkPolicyService` holds the effective Online, Offline, or LocalOnly mode. `AppSettings` combines the requested mode with the active workspace privacy setting; network-capable services check the effective mode at their transport boundary. Loopback remains available in Offline and LocalOnly. `SettingsService` exposes the requested and effective mode without claiming Internet connectivity from one provider result. `PrivacyService` projects current model, speech, credential, persistence, network, retention, and recovery state. `RetentionPolicy` stores versioned choices for completed chat, Agent runs, diagnostics, model source cache, and model operation history. Startup maintenance prunes bounded eligible records through owning stores; pinned chats and active work are preserved. Memory has no age policy. Captured audio and generated speech use after-use cleanup with stale Sentinel-owned artifacts removed on startup.

`RecoveryService` persists bounded typed conditions in an atomic, versioned status file. Import rollback failure records affected domains as `RecoveryRequired`. Newer or corrupt recovery status is exposed as recovery required rather than overwritten. `ModelOperationService` journals bounded Hugging Face download metadata; startup marks unfinished entries `Interrupted`, removes matching managed temporary artifacts, and does not retry downloads. Explicit resolution clears a model operation condition only after cleanup succeeds.

Plugin manifests may declare stable credential IDs, kinds, labels, and required state. `PluginManager` stores declared values in native secure storage and verifies readback. Plugin contexts can read only their own declared credential IDs; extension snapshots expose presence metadata. Reload refuses new or widened credential declarations. The current plugin manager does not persist or inject arbitrary plugin configuration, so it has no supported legacy plaintext credential fields to migrate.

`BackupService` exports a size-bounded versioned JSON document with selected portable settings, workspace profiles, remote MCP configuration, chat, and memory. Credentials, model binaries, and temporary data are excluded. Import validates the manifest and selected domains before writing, with explicit merge or replacement rules. It snapshots settings and memory before commit and tracks imported chat IDs for domain-owned rollback. Commit and rollback failures have distinct error codes; a rollback failure explicitly reports recovery required. This is bounded compensation across heterogeneous stores, not an atomic database transaction.

`OnboardingService` owns the versioned first-run step and completed-step list in the same settings store. Legacy completion remains authoritative for existing installations. New setup resumes at the saved step, permits local use without a model or cloud account, and makes speech optional. Finishing local setup applies a Local Only workspace preference without granting file or process access. The old informational appearance, use-case, and capabilities pages are no longer in first-run navigation; their legacy stored fields remain readable for migration compatibility.

Qt translations remain the localization mechanism. `ProductMessages` maps stable backend error IDs and typed parameters to presentation text; English is the fallback and Turkish translations are bundled. IDs used for persistence, providers, models, tools, and extensions are never translated.
