# SENTINEL — V3.2.5 FINAL REPORT

Date: 2026-10-10–11 (Europe/Istanbul; trace timestamps are UTC). Verdict: **NOT ACCEPTED — improvements verified, read-only user-task completion still requires fixes.** No V3.3 work was started.

1. **Reproduced root causes.** Read-task waits occur inside the separate plain intent-classification generation, before planning. Independent original Nemotron requests can succeed but consume substantial reasoning budget: one completes at 28.27 seconds with 366 reasoning tokens out of 437 completion tokens, versus a minimal JSON control at 2.39 seconds. This establishes request-dependent cost/variability, not the cause of every timed-out inference. A successful original response misclassifies content explanation as `exists`; long conversation also deterministically truncates the trusted workspace-root suffix. Exact production-policy probes still time out on both models after the prompt fix. The underlying provider-side cause of every stall is not established.

2. **Classification architecture.** ObservationIntentPolicy establishes evidence obligations and symbolic claim requirements, not filesystem/process permissions or concrete tool plans. AgentLoop fails closed on indeterminate intent. ToolExecutionGateway retains schema, approval, permission, authorization, resource and sandbox authority. No heuristic classifier bypass, model fallback or implicit tool grant was introduced. A future simplification must retain evidence obligations as well as gateway authorization.

3. **Implemented fixes.** Shorter prompt explicitly separates reading/explaining contents from existence questions and preserves the appended workspace root under bounded conversation. Classification retains 30000 ms/512 tokens. Native provider calls now honor per-request deadline/output options; planner calls use 120000 ms/1024 tokens, taking the bounded non-streaming path. Selected endpoint output builders preserve the appropriate native contract, including explicit Claude/Gemini bounds. Safe diagnostics add stage timestamps, trace/request IDs, internal/external session/run mapping, tool-request flags, final-gate outcome and verified/repeated-read counts. No prompt, source content, credentials or private reasoning is logged by them.

4. **Provider-specific results.** Nemotron GGUF Q4_K_M and Qwen MLX 4bit were tested sequentially at API-confirmed 8192 context/four slots without changing reasoning defaults. Nemotron completes classification in 3/16 actual task attempts; Qwen in 0/15. Both additional exact production-classifier probes fail at the enforced deadline. A final minimal Qwen control returns HTTP200/length in 28.28 seconds with all 511 completion tokens reported as reasoning and zero visible content, directly demonstrating failure of the 512-token visible-JSON contract for that request. These are results under the approved bounded contract, not claims of absolute model incapability. Concurrent build activity and different engines preclude a controlled speed ranking. Loaded-model metadata and all failed attempts are preserved.

5. **Tool-planning transition.** One natural Nemotron A flow reaches native planning, requests `read-file`, executes the real C++ gateway handler and transports a 99-byte actual tool result into continuation. First tool request is about 69.75 seconds after submission; the handler takes 7 ms. The initial final is rejected and repair starts, then the 150-second observer cancels the run. Classification success is never counted as task completion. Regression coverage proves successful classification without required evidence cannot complete, and indeterminate classification cannot plan.

6. **Live grounded-answer outcomes.** No A–D explanation satisfies the full observed-evidence/correct-answer/accepted-final chain. Nemotron E has two runtime completions, both generic directory/search receipts that fail the requested explicit missing-file response. They are not explanation successes. Deterministic resolver/real-gateway tests still validate current-run IDs and exact quotes; that does not substitute for live model task correctness. The exact reason for the first old-build final rejection cannot be reconstructed from its allowlisted metadata and is not invented.

Of **31 task attempts**, classification succeeds in **3 (9.68%)**, tools run in **3 (9.68%)**, one has a completed file-read result, runtime completes **2 (6.45%)**, and correct requested user-task success is **0/31 (0%)**. Initial Nemotron uses a preserved earlier source/binary snapshot; final-source controls/extra A and Qwen use the final binary. Hashes and patches distinguish them explicitly.

The complete lifecycle audit observes no late tool result, second terminal event, or cross-run tool-call ID. All synthetic fixture hashes remain unchanged; no write/process approval was allowed. Client abort does not prove upstream inference stopped. Task-owned model instances are removed after testing; final catalog evidence records restoration. Personal Keychain integration was not exercised; encryption regression uses the existing hermetic test key.

10. **Remaining blockers.** Approved-model classification is unreliable within the current bounds; no correct live explanatory final is accepted. Generic receipt acceptance still lacks a response-purpose relevance contract. Binding/native byte-budget estimates are not tokenizer measurements. Malformed semantic JSON reports indeterminate but does not yet have a dedicated parse-reason code distinct from transport success. Old-batch rejected-final details and concrete failed-run path/repeated-read mapping are limited by existing metadata. External branding artifacts prevent a green full-suite gate. Physical terminal-host validation, Linux comparison and macOS safe child-tree build execution remain separate gates; containment is not weakened.

11. **Final verdict.** **NOT ACCEPTED.** Finite client lifetime, fail-closed behavior, stage observability, a real read-gateway transition and deterministic grounding regressions are verified. Reliable grounded read-only task completion and the full regression gate are not achieved. No fake provider success, scripted model tool sequence, unsafe permission bypass, download, provider/settings fallback, personal-data modification, commit, push or merge was used.

12. **Recommended next phase.** Continue a bounded V3.2.6 reliability phase before V3.3: verify the approved models' classifier generation/schema/reasoning compatibility with explicit request-level evidence, establish a response-purpose contract that rejects receipt-only substitutes, and obtain repeated correct live explanatory finals. Resolve the external branding provenance conflict with its owner without deleting their assets or weakening the checker. Keep native terminal and safe macOS build acceptance separate.
