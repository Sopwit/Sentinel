# TUI V3.1 command validation

Completed 2026-10-10. This supplements the historical V3 command specification; the current registry has 44 entries including `/theme`. Registry coverage is not evidence of full live handler acceptance.

All names/aliases resolve through the typed registry and exhaustive handler; deterministic tests cover aliases, argument validation, context availability, unavailable explanations, slash matching, suggestions, popup/help rendering and registered bindings. Each row retains its source, permission classification and backend dependency. Help metadata and examples are generated from this source. Classifications do not grant daemon permissions.

IMPLEMENTED + VERIFIED below means the named core operation was exercised in a real TUI/daemon flow, plus deterministic coverage; it does not mean every alias/error permutation was live tested. EXISTING + REUSED means the underlying real daemon contract was exercised and TUI dispatch tested deterministically. Other implemented commands retain PARTIALLY VERIFIED status because their specific live UI action was not exercised. Disabled commands send no IPC and are SPECIFIED ONLY or DEFERRED. No command is promoted solely because it appears in the registry.

## Exact limits and failure evidence

- Actual TUI Help, model picker, session creation/browser, Agent switch, references, theme picker and exit were recorded. `/files` and `@` share the real authorized picker. File references are paths, not injected contents; Agent reads through daemon tools. Chat attachments remain unsupported.
- Resume/history persistence, rename, archive and populated JSON export were verified against a restarted disposable daemon. The export existed and contained the real Chat reply. An accepted invocation with a false boolean result now fails in the UI; regression tested.
- Invalid model selection was rejected. A discovery catalog is not initialization. A test initially selected before discovery stabilized and received `model-unavailable`; the harness now waits. This is not silently reclassified as successful selection.
- Provider/workspace creation and selection used actual daemon contracts. `/status`, `/doctor`, `/tools`, `/permissions`, `/mcp`, `/tasks`, `/memory`, `/context`, `/settings`, `/details`, `/activity`, `/history`, `/review` and supporting inspection actions retain deterministic/UI-contract verification only where no specific live action is recorded. Raw protected tool payloads are not exposed.
- Cancellation was tested through TUI Ctrl+C while approval was pending and IPC during streaming; approval y/n use the authoritative response contract. `/cancel` resolves to that same action, but its literal slash invocation was not separately live tested.
- Theme selection is process-local; `SENTINEL_TUI_THEME` sets launch preference and `NO_COLOR` overrides colors. No new persistent settings schema. Enter sends, Shift+Enter inserts newline on supporting hosts, Alt+Enter/Ctrl+O remain fallbacks. All aliases have deterministic resolution coverage, not individual live acceptance.
- `/plan` is disabled because authoritative non-mutating policy is absent. Undo/redo, compact, skill invocation, guided questions, external editor and init remain accurately unavailable. No shell shorthand exists.
